# Motion on the Civic AI Club site

Everything that moves on this site is asked for with a **data attribute** in the HTML. You never import GSAP or Lenis in a page or component; CI fails if you do (`npm run check:gsap`). All animation code lives in `src/scripts/motion/`.

See every effect on its own at **`/styleguide/`** (run `npm run dev` and open http://localhost:4321/styleguide/).

## The rules
- **Two curves only.** `expo.out` (fast start, long soft stop) for text and media, and `civic` (`M0,0 C0.7,0 0.3,1 1,1`, CSS `var(--ease-civic)`) for page changes, dividers and the marker. No bounce, no elastic.
- **Content first.** Everything is readable with JavaScript off or broken. Elements only start hidden when `<html>` has the class `js-motion`, and the module that animates them releases them (`is-split`, `is-drawn`, `is-open`, `is-ready`). If the motion code hasn't started 3.5 s after load, a safety net in `Base.astro` removes `js-motion`.
- **Reduced motion is respected.** If the visitor's device asks for reduced motion, or they switch **Motion: Off** in the footer, there is no preloader, no smooth scrolling, no text splitting, no scroll effects, no page-change animation, no header hiding, and videos show their poster with a Play button. Turning Motion back on restarts everything (page changes included) without a reload.
- **Animate only `transform`, `opacity` and `clip-path`** (the marker animates a background size, which is also cheap).
- **Every autoplaying loop has a visible Pause button.**

### Page changes: where the switch lives
- The `@view-transition { navigation: auto }` opt-in is written **inline in the `<head>` of every page** by `Base.astro` (with `navigation: none` under reduced motion), not in `transitions.css`. The browser decides whether to animate a page change as soon as the next page starts; the external style file sometimes hadn't arrived by then, and about half the page changes on phones were skipped with an uncaught "Transition was skipped" error. `transitions.css` only holds the `::view-transition-*` animations.
- **Motion: Off** adds `<style id="vt-off">@view-transition{navigation:none}</style>` after the opt-in (the head script on page load, `motion-toggle.js` when the switch is flipped; switching On removes it, so page changes animate again without a reload). As a second net, `pageswap`/`pagereveal` skip any transition that still starts, after `vt.ready.catch(() => {})`, so skipping never logs an error.
- **Speculation rules** (`Base.astro`): links marked `data-next-link`, `data-dk-hit` or `data-dk-open` are prerendered by Chrome when the pointer rests on them (`eagerness: moderate`), so the zoom hands over to a page that is already built. Keep those attribute names on the hand-off links. A prerendered page starts its motion (and the 3.5 s safety net) only when it is shown (`document.prerendering` / `prerenderingchange` in `index.js` and `Base.astro`), so its intro still plays for the visitor.

### Page-level switches (on `<Base>`)
- `preloader` — the paper sheet "Bring us the boring bits." plays on the first page of a browser session if that page is home (add `?preloader` to the address to force it while reviewing). Timing: words darken 0–0.55 s, the sheet lifts at 0.6 s (0.8 s `civic`) while the line holds still, header and CIVIC start on that beat, scrolling resumes at 1.0 s, done at 1.4 s.
- `intro="home"` — the header items drop in 0.06 s apart over 1.2 s on the intro beat.
- `preloadImages` — pictures the first screen needs, preloaded with `fetchpriority="high"`, e.g. `[{ href: '/media/home/…-poster.webp', media: '(max-width: 767px)' }]`.

| Event | Sent by | Meaning |
|---|---|---|
| `civic:motion` `{ enabled }` | footer switch | Motion turned on/off. |
| `civic:intro` | `core.js` | The page's intro beat. Use `onIntro(fn)` in modules instead of listening. |
| `civic:revealed` | `reveal-lines.js` (on the element) | That text finished rising. `mark.js` listens. |
| `civic:scroll-lock` `{ locked }` | `src/scripts/site/menu.js`, `home-docket.js` (during the zoom) | Pause/resume smooth scrolling. |
| `civic:cursor-refresh` | `video.js`, `home-player.js`, `home-docket.js` | An element's `data-cursor` changed; look again at what's under the pointer and update the label. |

## Adding motion for a page
1. Create `src/scripts/motion/modules/<page>-<thing>.js`. It is loaded automatically on every page.
2. Export a module object and do nothing if the page's element isn't there:
   ```js
   // docket.js: the home page docket (one plain-English line about what it does).
   import { gsap, ScrollTrigger, EASE, later, onIntro } from '../core.js';

   export default {
     name: 'docket',
     init() {
       const stage = document.querySelector('[data-docket]');
       if (!stage) return undefined;          // not on this page
       // ...make animations here; they are undone automatically when Motion is switched off...
       const onClick = () => later(() => gsap.to(stage, { opacity: 0.5 }));
       stage.addEventListener('click', onClick);
       return () => stage.removeEventListener('click', onClick);  // clean up listeners
     },
   };
   ```
3. Make things created later (on hover, click, a timer) through `later(() => ...)` so switching Motion off can undo them.
4. Hide-before-animate CSS must be scoped under `html.js-motion` and released by your module.
5. Add an example to `/styleguide/`, and a row to the table above.
6. Never edit someone else's module; add your own.

`core.js` offers: `gsap`, `ScrollTrigger`, `SplitText`, `EASE`, `motionAllowed()`, `hasFinePointer()`, `getLenis()`, `onIntro(fn)`, `onReady(fn)`, `later(fn)`, `numberAttr(el, name, fallback)`, `emit(name, detail, target)`, `killAll()`. The M9 helpers `rollText` / `rollThrough` are in `helpers/letter-roll.js`.

Modules that must work with motion off (like `video.js`) set `always: true`; they run once, outside the motion context, and must check `motionAllowed()` themselves.

## The pages

Each page's own motion is described below, in the order a visitor meets them: the home page, the case pages (and the 404), then About. Every page also uses the shared attributes above.

## Home page (`/`)

The home page is `src/pages/index.astro`, built from the components in `src/components/home/` (`HomeHero`, `HomeReel`, `Docket`, `DownTheRoad`, `Glance`) plus the shared `Statement`, `KeyValue` and `BigLink`. The hero, statement, key/value row, "Down the road" and the big link only use the attributes above (the preloader, `data-wordmark="hero"`, M1, M2, M4 `data-parallax="0.5"` on the hero's bottom row, M5 on "eats their week", M6, M7, `data-header-swap` on the reel). Page-wide starting positions are in `src/styles/home.css`.

### The docket (`Docket.astro`, `home-docket.js`)
The stacked list of letter windows is the default (phones, tablets, touch screens, motion off, no JavaScript): each window is a square with the docket clip (full color) under an ink SVG whose letter is an even-odd hole, and the whole window links to the case. With motion on and a mouse or trackpad at ≥ 1024 px (`(min-width: 1024px) and (hover: hover) and (pointer: fine)`), the module adds `is-stage`:
- The section becomes 500vh and `.docket__stage` sticks for 100vh. The case shown is `floor(progress × 5)` of that scroll (not scrubbed); the first one rolls in when the section's top reaches 65 %.
- Changing case: the old letter rolls out and the new one in (M9: yPercent ∓110 of the letter height, 0.9 s `expo.out`, direction follows the scroll), the footage cross-fades (0.4 s `civic`), and the words swap (the old words leave to −140 %, the new ones rise from 110 %, 0.9 s `expo.out`, 0.012 s apart, 0.12 s after). The rail's crimson underline hands over (M8, CSS).
- Beside the words, two ruled rows, "Built by" (the team without advisors, `Name ’YY`) and "Status", read from the case file (`data-dk-fact`). Their top rule sits at 62 % of the letter's height (level with A's crossbar); they swap on the name's timing, and only the current case draws its hairlines.
- Pointing at the letter: `is-hover` pushes the current clip's `.video__inner` in from scale 1 to 1.04 (0.6 s `expo.out`; the footage is already in color) and the cursor reads "Open Case A ↗" (it rolls through the letters between).
- Clicking the letter or "Open case": **the zoom**. The letter's hole grows around the deepest point of one of its strokes (from `docket-letters.json`) to about 40× (enough that the stroke covers every corner: `max corner distance ÷ stroke radius × 1.08`), 0.7 s `civic`, exponentially (scale = Z^p) so it feels steady; the footage grows from its square to cover the screen (0.7 s `expo.out`, keeping the hover push-in), with no dark layer; the words fade (0.3 s). Then the stage is named `view-transition-name: case-media-<slug>` (class `case-media`) and the case page opens, where its hero footage carries the same name (see "The footage hand-off" above). Cmd/Ctrl/Shift/middle clicks open normally. Back (bfcache) resets the stage.
- "List view": the letter rolls away, the names rise into a centered list (the current one in paper, the rest in `--paper-2`) and a small square window beside the current name shows its footage; pointing at a name moves the window there. "Full view" reverses it.
- Keyboard: tabbing to a case's "Open case" jumps the scroll to that case, so what has focus is on screen. The rail buttons scroll smoothly to a case (the letters roll through the ones between).
- Arriving straight on a case (the "Cases" link) shows its footage at once; the intro trigger then switches itself off, so the same clip doesn't fade out and back in.
- `.docket__stage` carries `data-header-keep`, so the header stays shown while the stage is pinned.

## Case pages (`/cases/<slug>/`) and the 404

The case page template is `src/pages/cases/[slug].astro`, built from the components in `src/components/case/`. Most of it uses the attributes above (M1 on the name, the chore and every row, M2 dividers, M3 on the close-ups, M4 on the hero and the next-case clip, M5 on the chore, M7 on links, `data-header-swap` on the chore section). Four things are its own, in `src/scripts/motion/modules/case-hero-grow.js`, `case-playhead.js`, `case-player.js` and `case-next.js` (shared helpers in `src/scripts/motion/helpers/case-playhead.js`).

### The case hero (`CaseHero.astro`, `case-hero-grow.js`)
- The hero is in normal page flow on ink. Top row: the mono meta line and the case name at `--fs-case-hero` (13vw on phones). The name rises straight away (M1), the meta 0.15 s later; `data-parallax="0.5"` makes the words drift at half speed, so the frame slides over them.
- Below: an inset exhibit frame from margin to margin, 16:9, or 4:5 at ≤ 767 px and on upright tablets up to 1100 px (the `<slug>-hero-mobile` cut, or `heroFocus` from the case file to crop the wide clip). Square corners, full color, no dark layer. The Pause button is an ink chip at the frame's top right. `data-header-solid` is on the words band and on the frame's outer box.
- `data-hero-grow` (on the frame's outer box, `case-hero-grow.js`): a scrubbed ScrollTrigger from scroll 0 until the frame's top meets the header's bottom scales the frame from 1 to `clientWidth ÷ frame width` (about 1.06 at 1440), transform-origin `50% 0`, transform only, re-measured on refresh. Nothing happens with reduced motion or Motion Off; switching Motion Off also clears the words' drift.
- The inner frame (`data-case-hero-media`) carries `view-transition-name: case-media-<slug>` (see the hand-off below).

### "How it works": scroll is the playhead (`Playhead.astro`)
| Device | What happens |
|---|---|
| Mouse or trackpad, 768 px and wider, motion on | The recording's track is 300vh tall and its stage sticks for 100svh (CSS, from `html.js-motion` and the media query `(min-width: 768px) and (hover: hover) and (pointer: fine)`). With p = scroll progress through the track (0 → 1): **0.15 → 0.55** the grey 16:10 window (columns 7–12) opens to the full screen and grayscale turns to color (the `civic` curve); the case letter, exactly as tall as the window, shrinks and fades out by the time the window is half open (a mono "Case A" tag sits in the bar instead). **0.15 → 0.95** sets `video.currentTime` (0 → the clip's end). Captions rise as the playhead passes each beat (0.85 s `expo.out`, 0.008 s apart; the old caption leaves at the same moment on `expo.out` over 2.2× as long, so one is always readable; scrolling back reverses both). The timecode and the 1px crimson progress line follow. Pomfret Voices shows a year counter instead: it is always the current beat's year, and the changed digits roll through the ones between (0.6 s `expo.out`); in year mode the bar captions drop their "YYYY. " prefix. The whole clip is fetched once as a blob when the track is one screen away; a new seek is only sent after the last one was drawn (`requestVideoFrameCallback`, with a `seeked`/timeout fallback). |
| Touch, or narrower than 768 px, motion on | No sticking or scrubbing. The clip loops while ≥ 25 % on screen, with a Pause button (an ink chip); beat 0 shows from the start (also when `play()` is refused), and the year and caption update together every frame (captions 1.4 s / 0.012 s). On touch screens ≥ 768 px the clip spans the full content width and the big letter is hidden. |
| Motion off (device setting or footer switch), or no JavaScript | Poster with a Play button (native controls without JavaScript). Every caption is written out under the clip with its timecode and full text (screen readers hear "At 0.5 seconds: …"); while it plays, the current one is lit (color only). |

| Attribute | On | Meaning |
|---|---|---|
| `data-playhead` | the track | Switches the chapter on. `data-duration` = clip length in seconds; `data-year-mode` = every beat starts with a year. |
| `data-playhead-stage` | the sticky stage | Carries `--open` (0 → 1, set by the scroll) and `--z0` (how far the footage is shrunk to fit the window at the start, measured on refresh). |
| `data-playhead-screen`, `data-playhead-window` | the footage box, an invisible box where the window starts | The window's size and place come from the grid in CSS; the invisible box lets the script measure it. The screen carries `data-header-solid`. |
| `data-playhead-video` | the `<video>` (H.264 scrub clip) | The clip that is scrubbed or played. |
| `data-playhead-letter`, `data-playhead-letter-inner` | the case letter and its inner span | The inner span rises (yPercent 115 → 0, 1.4 s `expo.out`) when the track's top reaches 70 % (80 % on touch). |
| `data-playhead-caption`, `data-playhead-hint` | caption lines in the bar | One per beat, stacked; the hint "Scroll to play" shows before the first beat (scroll mode only). |
| `data-playhead-clock`, `data-playhead-year`, `data-playhead-progress` | readouts in the bar | Timecode `00:04.2`, year counter (its year is also in `data-value`; the current caption gets `is-current`), progress line (`scaleX`). |
| `data-playhead-toggle`, `data-playhead-toggle-label` | the Play/Pause button | Shown on touch and with motion off; hidden in scroll mode. |
| `data-beat` + `data-t` (+ `data-year`) | each row of the written list | The beats, from the case file's `beats:`. |

To add a case, only the case file changes: its `beats:` (seconds into the `<slug>-scrub` clip) become the captions. Start every beat with a year ("1894. …") to get the year counter.

### The footage hand-off between pages (view transitions)
- The case hero's inner frame (`data-case-hero-media`, the inset rectangle, not the growing outer box) is always named `view-transition-name: case-media-<slug>` with `view-transition-class: case-media`. **To grow something into a case hero from another page, give it the same name just before leaving** (only when it's on screen and the visitor is going to that case). Two things do this today: the home docket's zoom (`home-docket.js`, which names its stage just before it opens the case) and the next-case window (`case-next.js`, at `pageswap`).
- The page that hands over also names its header bar `site-header` and leaves the case page a note: `sessionStorage` `civic:handoff` = the case's path. The case page's `pagereveal` listener (the first script in `Base.astro`) reads the note and, for the length of the page change only, adds the class `vt-handoff` to `<html>`. `case.css` then names the hero's words `case-hero-text` (above the frame, z-index 2, on its own ink strip) and the header `site-header`, so both sit above the arriving footage (the name rises over it; the header stays put, its two versions cross-fading in 0.4 s) instead of being hidden under it and popping in at the end. The old page drifts up 6vh without dimming, and the new sheet rises from the bottom as usual.
- `src/styles/case.css` (loaded only on case pages, the arriving page) styles it: the full-screen docket or next-band picture shrinks into the inset frame over `--dur-sheet` on `civic`, and the two pictures cross-fade on `civic` too; both fill the moving box (`object-fit: cover`); and a hero that arrives with no partner rises with the new sheet (`vt-sheet-in`) instead of floating in. No dark layer is used anywhere (footage is never veiled), so there is no brightness jump.
- At `pageswap` a case page always drops its own hero's name, so the hero never flies across the screen towards the next page; the names come back (and the header's is removed) if the visitor returns with Back (bfcache `pageshow`).
- Browsers without cross-document view transitions (Firefox today): the zoom still plays, then the case page simply opens. The next-case band skips its zoom there (it checks for `pageswap` support) and is a plain link.
